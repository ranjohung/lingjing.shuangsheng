# 后端需求评估与开发状态（2026-10-01）

## 结论

本项目要从静态演示升级为正式可用产品，必须开发并接入后端。当前 `index.html` 可以完成界面和本地演示，但不能承担账号安全、跨设备存档、真实经济账本、支付回调、内容版本和创作发布。

## 当前已存在

- `apps/api` 已有 FastAPI 入口、故事目录、故事会话、选择、回溯、命运卡接口。
- 故事模块已有 SQLAlchemy 存档仓储，可切换 SQLite/PostgreSQL，但默认配置仍未完成生产启用。
- 角色、记忆、关系和经济模块目前主要使用进程内内存。服务重启后会丢失。
- 认证未配置 Supabase 时固定放行 `local-dev-user`；即使配置了 Supabase，当前安全模块仍未真正校验 Bearer JWT。
- 前端主流程仍以 `localStorage` 为主，尚未形成登录用户到服务端存档的完整链路。

## 必须开发的后端范围

1. **认证与用户隔离（P0）**：真实 JWT 校验、用户身份、游客与正式账号边界、生产环境禁止 dev fallback。
2. **小说世界存档（P0）**：PostgreSQL/SQLite 迁移、版本绑定、并发 revision、跨设备读写、删除和导出。
3. **角色/记忆/关系持久化（P0）**：替换进程内字典，所有查询按用户隔离。
4. **平台与世界经济（P1）**：服务端余额、流水、幂等订单、支付回调验签；完成前继续标记为演示。
5. **创作流程（P1/P2）**：上传、解析、素材、版本、质检、发布权限与审计。
6. **任务与观测（P1）**：异步生成任务、成本熔断、日志、错误追踪、备份恢复。
