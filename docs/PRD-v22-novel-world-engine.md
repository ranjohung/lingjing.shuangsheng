## 1. 背景与定位

### 1.1 上一轮（V20-X）做错了什么

V20-X 是**沉浸式影视小说阅读**：把章节原文一字不差做成长滚动阅读，加章节封面 + 段落画面卡片 + 末选项。用户反馈："还不够，截图里的'古代种田文'只是模版之一。目标是**通用小说世界引擎**，上传任意小说自动生成玩法游戏。"

### 1.2 与 V21 的边界（**不混淆**）

| 命名空间 | 目标对象 | 核心动作 | 输出形态 |
|---|---|---|---|
| **V21-novel-sim**（已存在，独立） | 想写小说但不会写的新手作者 | AI **辅助**作者填问卷、写大纲、逐章创作 | 28 字段表单 + 三栏创作台 |
| **V22-novel-world-engine**（本次新建） | 想玩游戏但不想读大段文字的玩家 | 系统**自动**从已上传小说原文提取生成可玩游戏 | 全屏场景 + 悬浮标签 + 视觉小说 UI |

> V21 与 V22 是两条独立工作线，**可并行推进，互不依赖**。命名空间保持严格区分。

### 1.3 V22 核心定位

**"上传任意小说 txt → 自动判定题材（修仙/末日/武侠/经营/宫斗） → 自动抽取场景/NPC/道具/动作 → 自动生成对应题材的属性面板和悬浮标签 → 玩家在全屏视觉小说界面里点击标签推进剧情"**

**AI 的最高身份**：`提取器 + 排版器`（**不是作者**）。这是 S03 第一条铁律。

## 2. 核心原则（铁律优先级最高）

### P-1 零删减原则
主线剧情、对话、心理描写，必须 **100% 使用作者原文**（`original_text`），严禁 AI 改写、压缩、跳过。哪怕一个标点都不得删减。

### P-2 零创造原则
游戏里出现的所有场景、道具、NPC、行动选项、物品配方，必须**全部从原文中提取**。原文没写的，AI 绝对不能凭空捏造。

### P-3 提取而非生成
AI 的唯一合法工作是：**把文字自动转化成"可点击的交互点"和"背景图"**，而不是自己编剧情。

### P-4 视觉小说范式（不破不立）
- ✅ 全屏场景背景 + 人物立绘 + 悬浮标签 + 底部文字框
- ❌ 禁用聊天气泡（左侧头像 + 右侧气泡）
- ❌ 禁用"在小说正文下方单独开对话框"

### P-5 主线锚点 + 支线收敛
- 主线路径：玩家选择符合原著的选择时，**直接播放原著的下一段文字**
- 支线路径：玩家选择偏离原著的选项时，AI 才介入（受"世界观规则库"约束），且**必须在 2-3 次互动后强制收敛回原著的下一个大剧情节点**

## 3. 用户主流程（6 步链路）

```
[1] 进入小说世界引擎入口（novel-game.html）
   ↓ splash 屏：书名 + 「▶ 进入世界」+ 「📖 继续阅读 / 🔄 重新开始」二选一
[2] 选角（沿用 V20-X 的角色 mask + 5 traits：仁义/勇武/智慧/文雅/机敏）
   ↓
[3] 进入游戏主界面：
   顶部状态栏（Q版头像 + 时间 + 行动值 + 铜钱 + 银两）
   中间：全屏场景背景（首段场景）+ NPC 立绘 + 悬浮标签
   底部：半透明文字框（原文逐字打字机）
   ↓
[4] 点击悬浮标签触发互动
   例：点击「拾取」 → 原文逐字显示「你拾取了一些不错的木头」
                    → 背包 +3 木材
                    → 行动值 -1
                    → 状态栏数值跳动
   ↓
[5] 推进到下一场景 / 章节
   场景切换：全屏背景淡入淡出
   章节切换：触发章节封面（V20-X 已有）
   ↓
[6] 系统菜单（右侧 ✦ 浮动按钮唤起）
   存档 / 读档 / 回放 / 设置 / 商城 / 属性 / 衣柜 / 好感 / 福利
   「退出世界」回 splash（V20-Z 已实现）
```

## 4. 5 步自动化流水线（数据中枢建模依据）

| 步骤 | AI 任务 | 提取字段 | 映射到游戏 |
|---|---|---|---|
| **Step 1** 场景与时间 | 识别地点 + 时间 | `scene_id`, `scene_name`, `time_period` | 全屏背景图 + 顶部状态栏时间框 |
| **Step 2** NPC 与角色 | 识别出场人物 | `npc_id`, `name`, `relation` | 人物立绘 + 互动菜单（闲聊/关于/给予/离开） |
| **Step 3** 物品与资源 | 识别物品 + 资源 | `item_id`, `name`, `category`, `quantity` | 背包物品 + 拾取奖励 |
| **Step 4** 动作与经营 | 识别动作 + 配方 | `action_id`, `name`, `cost`, `gain`, `recipe` | 悬浮标签 + 工坊制作 |
| **Step 5** 背景与文案 | 识别环境描写 + 段落 | `bg_text`, `paragraphs[]`, `emotion` | 全屏背景图 + 底部文字框打字机 |

**禁止跳步**：V22-A 数据中枢严格按此 5 步建模，每步输出独立字段。

## 5. 多题材自动适配引擎（V22-B 核心）

### 5.1 五大题材预设模版

| 题材 | 属性面板 | 基础操作 | 识别关键词（前 10% 章节） |
|---|---|---|---|
| **模拟经营/种田** | 体力、铜钱、声望、土地等级、饱腹 | 种田、采集、烹饪、建造、买卖 | 土地/作物/收获/交易/金币 |
| **修仙/玄幻** | 修为、灵根、神识、寿元、灵气 | 打坐、炼丹、闭关、御剑、宗门任务 | 炼气/筑基/金丹/飞升/灵气 |
| **末日/废土** | 生命、精神、饥饿、辐射、物资 | 搜索、建设、抵御尸潮 | 丧尸/辐射/避难所/物资/感染 |
| **武侠/江湖** | 气血、内力、武功境界、江湖声望、善恶 | 比武、行侠仗义、修炼内功、结交豪杰 | 门派/内力/招式/江湖/比武 |
| **宫斗/宅斗** | 位分、宠爱、心计、礼仪、势力 | 请安、送礼、拉拢、陷害 | 后宫/位分/宠爱/势力/心计 |

### 5.2 权重叠加

系统读完小说前 10% 后，自动判定**多个题材权重**（例：修仙 70% + 门派经营 30%），动态组合 UI（同时显示"打坐修炼"和"管理药田"按钮）。

### 5.3 题材识别算法（V22-B mock 实现）

```js
// 简化版（不接真 LLM，本地关键词频次统计）
function detectGenre(paragraphs) {
  const weights = { xiuxian: 0, mori: 0, wuxia: 0, jingying: 0, gongdou: 0 };
  for (const p of paragraphs) {
    weights.xiuxian += (p.match(/炼气|筑基|金丹|飞升|灵气/g) || []).length;
    weights.mori    += (p.match(/丧尸|辐射|避难所|物资|感染/g) || []).length;
    weights.wuxia   += (p.match(/门派|内力|招式|江湖|比武/g) || []).length;
    weights.jingying+= (p.match(/土地|作物|收获|交易|金币/g) || []).length;
    weights.gongdou += (p.match(/后宫|位分|宠爱|势力|心计/g) || []).length;
  }
  const ranked = Object.entries(weights).sort((a,b) => b[1]-a[1]);
  return { primary: ranked[0][0], weights, combo: ranked[0][1] > ranked[1][1] * 2 ? [ranked[0][0]] : [ranked[0][0], ranked[1][0]] };
}
```

## 附录 B：术语表

| 术语 | 释义 |
|---|---|
| **原著锚点**（True Path） | 小说原文中的关键剧情节点，玩家不偏离时直接播放下一段原文 |
| **悬浮标签**（Hot Tag） | 场景背景图上带小三角的可点击标签，触发交互动作 |
| **支线收敛**（Convergence） | 玩家选偏离选项后，2-3 次互动强制回到主线锚点 |
| **世界宪法**（World Bible） | Step 1 输出的小说世界观规则库（题材/时代/力量体系/势力/禁忌规则） |
| **资产库**（Assets） | Step 2-4 提取的实体（场景/NPC/物品/动作/配方） |
| **剧情节点树**（Story Node Tree） | Step 3 输出，按原文章节切分并标注锚点的主线结构 |
