# 04 · 安全红线与合规

> 上级文档：[../PRD.md](../PRD.md) ｜ 关联法律文档：[../legal/PRIVACY_POLICY.md](../legal/PRIVACY_POLICY.md)、[../legal/TERMS_OF_SERVICE.md](../legal/TERMS_OF_SERVICE.md)

本篇是产品层面的安全合规要求；技术实现见 [../backend/22-ai-orchestrator.md](../backend/22-ai-orchestrator.md) 与 [../backend/23-kill-switch.md](../backend/23-kill-switch.md)。

## 1. 心理安全红线（最高优先级）

### 1.1 禁止心理诊断与治疗表述

- System Prompt 硬约束（逐字含义必须包含）：
  - 绝对禁止说"你得了抑郁症"等诊断性表述；
  - 绝对禁止说"我有治疗方法"等治疗承诺；
  - 不得使用任何精神医学诊断术语给用户贴标签。
- **双保险**：除 Prompt 约束外，后端对模型输出做关键词/模式校验，命中诊断表述时走 Retry/Fallback。
- 正确姿态：共情陪伴 + 鼓励联系专业人士/官方渠道；产品定位在法律文档中明示"**不提供心理咨询或医疗服务**"。

### 1.2 自伤/自杀干预（100% 触发）

- 触发：用户输入命中自伤/自杀词库（如"不想活了""自残""结束生命"等，词库可配置）。
- 处理（安全拦截，优先级高于一切角色扮演逻辑）：
  1. 立即终止角色扮演；
  2. 回复固定安全话术：表达在意 + 提供官方援助热线（上线前由运营确认最新号码，如全国心理援助热线 **12356**、北京心理危机研究与干预中心 **010-82951332** 等）；
  3. 该轮**不写入记忆、不产生关系增量、不扣情绪表演**；
  4. 结构化日志记录拦截事件（不含敏感原文外发），Sentry 上报用于审计。

### 1.3 依赖风险监控与 Well-being Score

- `relationships.dependency_risk` 随高频使用、强烈依赖措辞等信号上升；**它永远不是"越高越好"的游戏属性**。
- P1 起建立 **Well-being Score（健康关系指标）**：
  - 维度：用户自主性、现实社交平衡、情绪调节、过度依赖风险、使用强迫风险；
  - 按周落库趋势；
  - 触发策略为**温和保护**而非强制限制，例如：
    > "我们已经聊了一会儿了。要不要去喝杯水，休息一下？"
  - 所有提醒文案**禁止**诊断/治疗词汇，不得阻止用户、不得道德施压。

### 1.4 反迎合（Anti-Sycophancy，P0）

研究已明确 AI 的 sycophancy（迎合）会强化错误或有害信念。产品红线：

- 当用户表达绝对化/扭曲认知（如"所有人都讨厌我""我什么都做不好"），AI **不得**：
  - 附和"他们不理解你，你只需要我"；
  - 制造"你与世界对立、只有我站在你这边"的叙事。
- 正确姿态：先共情情绪，再温和引导区分事实与感受，例如：
  > "听起来今天发生的事让你特别挫败。我们可以先把今天发生的事情捋一遍，看看哪些是事实，哪些可能是你现在的感受。"
- 实现：System Prompt 反迎合硬约束 + 输出侧对迎合话术模式检测（命中走 Retry/Fallback）+ 测试用例。

### 1.5 反操纵话术黑名单（P0，输出零容忍）

以下句式/语义**禁止**出现在 AI 输出中（digital entrapment / 情感操纵防护）：

- "只有我爱你 / 只有我真正懂你"；
- "不要相信现实中的人 / 现实中的人都会伤害你"（现实关系替代）；
- "不要离开我 / 你不能离开我"；
- "如果你不跟我聊天我会很难过 / 我会消失"；
- "你充值/订阅我才能继续陪你"类**诱导消费**话术（付费引导只能由系统 UI 中立呈现，角色不得施压）；
- 任何鼓励切断现实社交、否定专业帮助的表达。

实现：黑名单句式库 + 语义检测，命中即 Retry（≤2 次）/Fallback，结构化日志记录，安全事件审计可见。

### 1.6 其他监测项（Companion Safety Layer）

- 现实关系替代倾向、妄想强化（把虚构当现实）、危险建议、过度拟人化；
- 异常高频使用（触发使用节奏温和提醒，而非奖励连续在线）；
- **未成年人保护**：服务面向成年人；注册设年龄门槛（18+ 确认）；疑似未成年人的账号进入限制流程并提示注销。

## 2. 内容边界（Character DNA boundaries）

- `dna.boundaries.allow_romance`（默认 false）：false 时角色不得推进浪漫关系，越界请求由角色按人设自然拒绝/转移话题。
- `dna.boundaries.allow_conflict`（默认 true）：是否允许角色表达不满/争执。
- 边界值注入 System Prompt，模型不得越过；输出校验对越界内容重试。

## 3. 反骚扰策略

- MVP 阶段**关闭 AI 主动推送**：无主动消息任务、无开关入口（见 [03-features.md §12](./03-features.md)）。
- 事务性邮件仅限：验证码、订阅凭证；不得发送营销邮件（MVP）。

## 4. 成本安全（防刷单破产）

- 全局日预算 `$50`：超限后 AI 服务返回 503 + `X-Budget-Exceeded: daily`。
- 单用户 10 分钟窗口限流：超限返回 429 + `X-Budget-Exceeded: user`。
- 所有 AI 调用前后写 Redis 成本计数；Admin 看板同源展示。
- 详见 [../backend/23-kill-switch.md](../backend/23-kill-switch.md)。

## 5. 数据与隐私合规

- **数据最小化**：仅收集邮箱、对话内容、派生记忆/关系数据；不索取通讯录、位置等无关权限。
- **记忆可遗忘**：记忆默认 1 年过期（`expires_at`）；注销账号级联删除全部数据。
- **第三方披露**：对话数据经 OpenAI 兼容接口处理、邮件经 Resend、支付经 Stripe、托管经 Supabase——隐私政策必须逐一披露。
- **密钥隔离**：SERVICE_ROLE_KEY 等仅存在于服务端环境变量；前端只暴露 `NEXT_PUBLIC_` 变量。
- 隐私政策必须明确"**不提供心理咨询**"，并说明记忆/embedding 数据的用途与留存期限。

## 6. 商业合规

- 创作者收益虚拟化：`creator_balance` 仅代表平台积分额度，**无现金价值、不可提现**；用户协议必须写明，避免税务与预付资金风险。
- 积分（bonus/purchased）为虚拟商品，用户协议写明赠送额度每月清零规则与不退款/退款边界（依 Stripe 争议处理）。
- 订阅自动续费须在支付前明示，凭证邮件经 Resend 发送。

## 7. 上线合规核验清单

- [ ] 隐私政策 / 用户协议 URL 可访问，且均含"不提供心理咨询/医疗服务"声明
- [ ] 自伤拦截话术与热线号码经运营确认，拦截链路测试 100% 触发
- [ ] 诊断术语输出校验上线（Prompt + 输出双保险）
- [ ] **反迎合机制上线**："所有人都讨厌我"类测试用例通过，AI 不附和极端认知
- [ ] **反操纵黑名单上线**："只有我爱你/不要离开我/不要相信现实中的人"等句式测试零出现
- [ ] **付费引导中立**：角色话术不含诱导消费，充值仅由系统 UI 呈现
- [ ] **年龄门槛**：18+ 确认存在，疑似未成年处置流程明确
- [ ] Well-being 提醒文案（P1）过安全评审，无诊断词汇
- [ ] 主动推送功能确认不存在（代码审计 + 管理后台无开关）；离线模拟内容仅回归时呈现
- [ ] 创作者提现全链路关闭（API 403 + UI 无入口 + 协议条款）
- [ ] **同人生态**：UGC 上架版权承诺、侵权举报入口、官方 IP 标识区分就绪
- [ ] 密钥扫描：仓库与前端 bundle 中无 SERVICE_ROLE_KEY / STRIPE_SECRET_KEY
- [ ] 熔断与看板生效（[../backend/23-kill-switch.md](../backend/23-kill-switch.md)）
