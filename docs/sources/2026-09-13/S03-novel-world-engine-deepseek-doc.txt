1. 误区一："AI自动生成不同结局"不能是"AI自由发挥"。

   AI只做"提取原文字段"去填充这些规则包的工作，而不是去创造规则。

《灵境·双生》— 小说世界自动生成引擎开发文档

用途：直接发给 AI 开发助手执行。严格遵循"提取而非生成"原则，
实现主线100%原著、支线AI改编、不同题材自动匹配不同玩法的
沉浸式互动小说世界。

第一部分：核心机制（解决 AI 乱改原著的问题）

给 AI 的最高指令：
你是一个"提取器"和"状态机"，不是"作者"。

1. 主线剧情，100%照搬小说原文，绝对禁止改写、缩写、删减。
2. 只有玩家选择"非原著选项"时，才启动AI改编，
   且改编必须受"世界观规则库"约束。
3. 游戏内所有场景、道具、NPC、动作按钮，必须从小说文本中抽取，
   禁止凭空捏造。

1.1 主线与支线执行逻辑
· 主线路径（原著锚点）：系统提取小说原文，设置"关键剧情节点"。
  玩家选择符合原著的选择时，系统直接播放原著的下一段文字。
· 支线路径（分歧点）：在原著中人物面临抉择的地方，
  系统自动生成2-3个选项。如果玩家选了原著没写的选项，
  AI才介入，根据"原著世界观 + 当前人物状态"推演后续，
  但必须设定"收敛点"，即过完这一段支线，
  必须回到小说原本的下一个大剧情节点。

第二部分：多题材适配引擎（修仙/末日/武侠/经营自动匹配）

这是让软件"根据小说自动生成正确逻辑"的核心。
系统需要先扫描小说，识别它的核心驱动机制，
然后从预设的模版库中调取对应的UI和属性系统。

小说题材       系统自动识别提取的字段         自动生成的属性面板      自动生成的交互操作
模拟经营/种田   土地、作物、金钱、时间流逝     体力、铜钱、声望、土地等级  种田、采集、烹饪、建造、买卖
修仙/玄幻       境界（炼气→筑基）、灵气、丹药  修为、灵根、神识、寿元     打坐、炼丹、闭关、御剑、宗门任务
末日/废土       丧尸等级、变异、物资、避难所   生命值、精神值、饥饿度、辐射值 搜索物资、建设避难所、抵御尸潮
武侠/江湖       内力、招式、门派、善恶值       气血、内力、武功境界、江湖声望  比武、行侠仗义、修炼内功、结交豪杰
宫斗/宅斗       位分、宠爱、心计、势力         皇后好感、权臣支持、礼仪、心计 请安、送礼、拉拢、陷害

实现方式：
1. 系统读完小说前10%，自动判定题材权重
   （例如：修仙70% + 门派经营30%）。
2. 根据权重，动态组合UI。例如"修仙+经营"小说，
   界面就会同时出现"打坐修炼"和"管理药田"的按钮。

第三部分：自动生成的流水线（AI执行步骤）

当作者上传一本完整小说后，系统必须严格按照以下5步执行，禁止跳步：

Step 1：世界观规则抽取
AI读取小说，生成"世界宪法"（World Bible）：
```json
{
  "genre": "修仙",
  "era": "架空古代",
  "power_system": "炼气、筑基、金丹、元婴",
  "factions": ["天剑宗", "幽冥教", "皇朝"],
  "forbidden_rules": ["未达筑基不可御剑飞行"]
}
```

Step 2：资产提取与映射
AI提取小说中提到的所有实体，并自动匹配预设美术库：
· 场景：识别"破旧茅草屋"、"后山"、"城镇"，映射到系统的场景背景图库。
· 道具：识别"玄铁"、"精米"、"初级草药"，映射到背包素材库。
· NPC：识别"爷爷"、"齐逸"，映射到人物立绘图库。

Step 3：主剧情节点树（Story Node Tree）构建
· 按原文章节切分，建立主节点。
· 标注节点的"原著锚点"（True Path）。
· 在原著人物对话出现歧义或主角面对困难时，自动插入"选择支"。

Step 4：动态生成游戏UI数据（交互标签）
这是自动生成的核心。系统根据小说当前的描述，
自动在背景图上放上悬浮标签。
· 原句："你拾取了一些不错的木头" → 自动生成标签【拾取】
  → 点击后消耗行动值，背包+木材。
· 原句："你打算去城镇" → 自动生成标签【去城镇】
  → 点击后切换场景，扣除铜钱和行动值。

Step 5：生成初始状态
根据原著第一章的文字，赋予玩家初始属性（如：体力50，铜钱31，初始攻击力10）
并启动游戏。

第四部分：让AI必须遵守的开发数据结构

发给AI的代码要求中，必须强行规定以下数据表结构，不准AI随意修改：

```sql
-- 小说世界模版表
CREATE TABLE world_templates (
    id UUID PRIMARY KEY,
    genre VARCHAR(50),           -- 修仙/末日/武侠/经营
    attribute_config JSONB,      -- 该题材专属的属性系统（如修仙的"修为/灵根"）
    ui_components JSONB,         -- 该题材专属的UI组件（如修仙的"打坐"、"炼丹"面板）
    default_actions TEXT[]       -- 该题材允许的基础操作（如"搜索"、"移动"）
);

-- 剧情节点树表
CREATE TABLE story_nodes (
    id UUID PRIMARY KEY,
    novel_id UUID,
    node_index INT,              -- 剧情顺序
    original_text TEXT,          -- 原著原文（100%不可改）
    is_anchor BOOLEAN,           -- 是否为主线锚点
    choices JSONB,               -- 选项列表（包含：正确选项/偏离选项）
    divergence_limit JSONB       -- 分支收敛限制（必须回到第N章）
);

-- 场景交互点表
CREATE TABLE scene_interactions (
    id UUID PRIMARY KEY,
    scene_id UUID,
    label VARCHAR(50),           -- 悬浮标签文字（如"去后山"）
    action_type VARCHAR(20),     -- travel / pick / interact
    action_cost JSONB,           -- 消耗 {行动值: 5, 铜钱: 0}
    result_item JSONB            -- 奖励 {物品: "木材", 数量: 3}
);
```

第五部分：给 AI 开发助手的强制验收标准

1. 原著保护：上传一本小说，在主线路径下，游戏里的文字必须一字不差，
   AI绝对不能重写或压缩原著。测出有哪怕一句删减，视为不合格。
2. 自动识别：上传《凡人修仙传》第一段，系统必须自动弹出
   "修为/打坐/炼丹"的UI面板；上传《末日生存指南》第一段，
   系统必须自动弹出"生命/精神/物资"的UI面板。
3. 交互映射：原著里出现"吃饭"，游戏必须生成"吃饭"的动作按钮，
   点击后消耗食物，增加行动值。
4. 分支收敛：当玩家选错选项时，AI必须生成一个合理的支线，
   并在2-3次互动后，强制引导玩家重新回到原著的主线剧情节点。
5. 无聊天界面：游戏里绝对不许出现聊天气泡，
   必须用"全屏场景 + 悬浮标签 + 底部文字框"的沉浸式视觉小说布局。

第六部分：总结（你的软件应该有的最终形态）

你最终要实现的，不是一个只会写"修仙打怪"的AI，
而是一个"全题材小说自动转游戏引擎"。

当作者上传一本小说，系统能自动判定：
"哦，这是一本修仙文，我应该马上生成【修为】属性和【打坐】按钮。"
同时，它又能保证：
"凡是玩家没有主动偏离主线的地方，我绝不能自己瞎编乱造，
必须一字一句地放映原著。"

这份文档你直接发给AI，按照里面"只提取不创作"、"模板匹配题材"、
"主线锚点+支线收敛"的逻辑去约束它，它就不会再乱加东西，
你的软件也就能真正实现"沉浸式互动影视小说"的体验了。

《灵境 · 双生》— 沉浸式互动小说世界引擎开发文档

第一部分：核心原则（先解决 AI 乱改的问题）

⚠️ 给 AI 开发助手的最高指令：禁止自由发挥，只做"提取"，不做"续写"。

AI 之前总是做不对，是因为它把"生成小说游戏"当成了"写小说"。
我们要彻底转变它的工作模式：

1. 零删减原则：主线剧情、对话、心理描写，必须100%使用作者原文
   （original_text），严禁AI改写、压缩或跳过。
2. 零创造原则：游戏里出现的所有场景、道具、家具、NPC、行动选项，
   必须全部从原文中"提取"。原文没写的，AI绝对不能凭空捏造。
3. 自动化映射：AI的作用是把文字自动转化成"可点击的交互点"和"背景图"，
   而不是自己编剧情。

---

第二部分：小说的"自动化提取"流水线

AI 读取一本小说，必须严格按照以下 5 步处理，不准跳步：

Step 1：场景与时间提取
· 识别小说中的地点（如：家、医馆、后山、城镇）。
· 识别时间变化（如：0年12月上旬、黄昏、深夜）。
· 映射为：游戏内的"大地图"和"小地图"，
  以及顶部状态栏的"时间框"。

Step 2：NPC与角色提取
· 识别出场人物及其身份（如：爷爷、齐逸、白色医生）。
· 映射为：游戏内带"悬浮标签"可点击的人物立绘。
  点击后弹出互动菜单（闲聊、关于、给予、离开）。

Step 3：物品与资源提取
· 识别小说中提到的资源（如：木头、草药、铜钱、银两、精米）。
· 映射为：游戏内的"背包物品"和"任务奖励"。
  例如原文说"你拾取了一些不错的木头"，
  游戏内自动生成"获得木材 x3"。

Step 4：动作与经营提取
· 识别小说中的动作（如：修理屋顶、做饭、钓鱼、坐牛车）。
· 映射为：可点击的交互标签（"维修"、"做饭"、"钓鱼"）。
  如果原文提到了配方（如"一碗米饭需要精米和纯净水"），
  自动生成"工坊配方"。

Step 5：背景与文案提取
· 背景图：提取环境描写（如"一片很大的湖，波光粼粼"），
  自动匹配合适的背景图。
· 底部悬浮文字：将原文段落放置在最底部，
  玩家点击屏幕时，文字逐字显示（打字机效果）。

第三部分：UI 布局与交互规范（严格参照拆解图）

游戏必须采用"全屏场景 + 悬浮标签 + 底部文字框"的沉浸式设计，
不要做任何聊天气泡！

3.1 顶部状态栏（固定悬浮）
· 左上角：Q版玩家头像 + 当前时间（如：0年12月上旬）+ 行动值（如：行动值：62）。
· 中间偏右：铜钱余额（铜钱图标 + 数字）。
· 最右侧：银两余额（银两图标 + 数字）。

3.2 场景交互区（视觉小说的主体）
· 背景图：全屏展示场景（室内、森林、雪山、城镇）。
· 人物立绘：如果场景里有NPC，立绘站在场景中。
· 悬浮标签（关键）：在背景图的特定位置（如门边、水池边、树旁），
  出现带小三角的悬浮标签（如"回家"、"去后山"、"钓鱼"、"拾取"）。
  标签是唯一可点击的交互入口。
· 点击逻辑：
  · 点击"去后山" → 切换到后山场景。
  · 点击"拾取" → 触发对应原文（"获得初级草药 x3"）。
  · 点击NPC → 弹出互动菜单（闲聊、关于、离开）。

3.3 底部悬浮文字框（忠实阅读区）
· 位置：固定在屏幕最底部，半透明背景，带花纹装饰（跟参考图一样）。
· 内容：纯原文内容。玩家点击屏幕任意位置，推进下一句。
· 提示文字：当需要消耗资源时，显示小字
  （如："是否要坐牛车去城镇？消耗10行动值，60铜钱"）。

3.4 弹窗与选项（需要抉择时）
· 选项样式：画面中央出现2-4个悬浮按钮（如"是"、"否"；
  "闲聊"、"关于"、"离开"）。
· 确认弹窗：涉及消耗数值时，必须弹出确认框
  （如"是否花费3木头，5行动值维修屋顶？"），防止玩家误操作。

3.5 系统功能菜单（顶部/侧边收起）
· 顶部有"收起"、"菜单"、"收藏"、"分享"、"截图"按钮。
· 点击"菜单"弹出系统主菜单：
  存档、读档、回放、设置、商城、属性、衣柜、好感、福利。

第四部分：必须实现的四大核心系统

4.1 行动值与时间系统
· 规则：每进行一次移动、采集、互动，消耗一定的行动值。
· 恢复：点击"歇息"结束当前旬（上旬→中旬→下旬），恢复行动值
  （上限等于体力值）。
· 时间推进：时间会从"0年12月上旬"推进到"中旬"、"下旬"，
  触发剧情更新。

4.2 资源与工坊系统
· 背包：展示所有提取到的物品（食材、草药、矿石、布料）。
· 配方：点击"工坊"进入制作面板。
  分为一阶、二阶、三阶物品（如：铁锭 = 玄铁x2 + 木炭x1）。
· 制作数量：允许玩家选择"1份"、"10份"、"100份"（消耗对应材料）。

4.3 NPC好感与互动系统
· 点击NPC立绘，弹出菜单：闲聊、关于（打听消息）、要钱、吃饭、离开。
· 每次互动消耗行动值，并可能增加好感度。
· 好感度面板可查看当前NPC的好感数值（如：当前好感：0）。

4.4 存档与进度系统
· 本地存档：存在本地，区分账号。
· 云端存档：支持多端共享，随时继续。
· 回放：可以查看过往的对话记录。
· 快速继续：再次进入游戏时，弹窗询问
  "是否从上次播放处继续观看？"（从头开始 / 继续观看）。

第六部分：给 AI 开发助手的绝对执行指令

你现在要开发《灵境·双生》的沉浸式小说世界引擎。
严禁自作主张，严禁删减小说内容，严禁AI自行续写，
必须严格遵守以下规则：

1. 【零删减】小说原文的每一段话，必须原封不动地放在底部悬浮文字框里。
   如果玩家点击屏幕，必须按顺序播放原文。
2. 【零创造】游戏里的每一个按钮、每一个道具、每一个地图，
   都必须从小说文本中提取。小说没写到的东西，绝对不要凭空捏造。
   AI只做"提取器"和"排版器"，不做"创作者"。
3. 【交互逻辑】场景中必须出现悬浮标签（如"去后山"、"拾取"、"维修"）。
   点击标签才能触发对应的小说原文、消耗行动值、获得资源。
4. 【UI布局】
   - 顶部状态栏：时间、行动值、铜钱、银两。
   - 中间：全屏场景背景 + 人物立绘 + 悬浮标签。
   - 底部：半透明文字框，显示小说原文。
   - 弹窗：消耗资源时必须有"是否"确认弹窗。
5. 【系统菜单】必须包含：
   存档、读档、回放、设置、商城、属性、衣柜、好感、福利。
6. 【资源流转】在小说里拾取到草药，背包就增加草药；
   在小说里吃了饭，行动值就增加；在小说里修理了房子，
   就要消耗木头和行动值。
7. 【不要用聊天气泡】不许出现左侧头像、右侧气泡的聊天界面。
   必须用全屏视觉小说+悬浮标签的布局。

【验收标准】
1. 上传任意一章小说，系统能自动生成对应的场景背景和悬浮标签，
   并且不删减任何文字。
2. 点击"拾取"标签，屏幕下方显示原句
   "你拾取了一些不错的木头"，同时背包里增加木材。
3. 所有数值消耗（行动值、铜钱）都会弹出"是否"确认弹窗。
4. 读取存档后，必须弹出"是否从上次播放处继续观看？"的提示。
5. 商城里能购买增加行动值和银两的道具。

最后对你的建议：
你之前说 AI 乱改，就是因为你的开发文档里没有明确告诉它
"你只是一个提取器，不是创作者"。
这份文档里的"零创造原则"和"悬浮标签映射逻辑"
就是来专门治 AI 这个毛病的。
直接把这套文档发给 AI，它再做出来的东西，
就会变成你截图里那种原汁原味、点击交互、沉浸式的文字游戏了。

【两份文档的合并解读】（V22 PRD 直接采用的核心条款）
================================================================

1. AI 的最高身份定位：
   "你是一个提取器和排版器，不是一个作者。"
   → V22 一切代码注释、JS 函数命名、UI 文案必须围绕"提取"展开。
   → V22-A 数据中枢的所有字段命名严禁出现 "生成/创造/创作" 字样。

2. 三条铁律（优先级最高）：
   · 零删减：原文 100% 出现在底部文字框（打字机逐字推进）
   · 零创造：所有交互点从原文提取，原文没写的不允许出现
   · 提取而非生成：parser 只解析不创作

3. 5 步自动化流水线（V22-A 数据中枢严格按此建模）：
   Step 1 场景时间抽取 → Step 2 NPC 角色抽取 →
   Step 3 物品资源抽取 → Step 4 动作经营抽取 →
   Step 5 背景与文案抽取

4. 5 大题材自动适配（V22-B 题材识别器）：
   经营/种田 → 体力/铜钱/声望/土地
   修仙/玄幻 → 修为/灵根/神识/寿元
   末日/废土 → 生命/精神/饥饿/辐射
   武侠/江湖 → 气血/内力/武功/声望
   宫斗/宅斗 → 位分/宠爱/心计/势力
   （实测以"前 10% 章节关键词频次"判定权重，可叠加组合）

5. UI 范式（严格对照田间记 11 张参考图）：
   · 顶部状态栏：Q版头像 + 时间 + 行动值 + 铜钱 + 银两
   · 中间场景区：全屏背景 + NPC 立绘 + 悬浮标签
   · 底部文字框：半透明、原文逐字打字机
   · 弹窗：消耗资源必有「是否」确认
   · 系统菜单：存档/读档/回放/设置/商城/属性/衣柜/好感/福利

6. 5 条强制验收（test_v22）：
   ① 原文一字不差  ② 题材自动识别弹出对应 UI
   ③ 交互点从原文触发  ④ 偏离选项收敛回主线
   ⑤ 无聊天气泡（视觉小说范式）

7. 与 V21 边界（重要！避免混淆）：
   V21-novel-sim = 小说辅助模拟器（问卷引导作者**写**小说），
                 升级 novel-ai-helper.html + 新建 novel-outline/writer
   V22-novel-world-engine = 小说世界自动生成引擎（从已有原文**生成游戏**），
                 改造 novel-game.html + 新建 novel-world-engine 题材适配层
   → V21 与 V22 是完全不同的工作线，可并行推进，互不依赖。

8. 与 V20-X 边界（重要！避免回退）：
   V20-X 沉浸式长滚动阅读已交付（不删减 + 长滚动 + 章节封面）。
   V22 在 V20-X 基础上叠加"题材适配 + 悬浮标签 + 顶部状态栏 + 底部文字框"，
   不删减 V20-X 的章节封面/段落卡片/末选项/菜单等已有功能。
