《灵境 · 双生》—— 小说辅助模拟器：实现方案与界面设计文档
================================================================

前序状态：已确认现有 AI 辅助系统的骨架（问卷式引导+创作简报+大纲生成+章节规划），
下面是小说创作 AI 辅助系统（小说辅助模拟器）的核心实现方案和界面设计。

一、核心实现目标
1. 大纲锁定，防止跑偏
   - 一旦作者确认大纲，后续所有章节生成必须围绕已确认的剧情主线进行。
   - 大纲锁定后，AI 只能在已确认的大纲框架下进行扩展和润色，
     而不能改变核心剧情、人物关系、关键事件。
2. 上下文感知，内容连贯
   - AI 生成每一章时，必须参考：已确认的大纲、人物小传、前面章节的结尾、
     当前章节的规划目标。
   - 通过上下文管理，确保章节之间的过渡自然，人物行为符合之前的设定。
3. 多选项生成，尊重作者主导
   - 每次 AI 生成内容时，给作者提供 3-5 个候选方案。
   - 作者可以选择一个方案，也可以"换一批"，或点击"我来说"手动输入想法。

二、数据模型（5 张核心 SQL 表）
1. novel_outlines（大纲表）
   outline_id / novel_id / theme / background / main_plot / ending_direction /
   turning_points(JSON) / status(draft,confirmed,locked) / confirmed_at
2. novel_chapter_plans（章节规划表）
   plan_id / novel_id / chapter_number / chapter_goal / main_conflict /
   characters_involved(JSON) / key_events(JSON) / connection_to_previous /
   connection_to_next / status(planned,writing,completed) / created_at
3. character_profiles（人物小传表 · 扩展现有）
   character_id / novel_id / name / role / personality /
   language_fingerprint(JSON: 语气/口癖/常用词/禁用词) /
   behavior_constraints(JSON: 永远不会做/总是做) / created_at
4. foreshadowing_tracker（伏笔追踪表）
   foreshadow_id / novel_id / content / introduced_chapter /
   resolution_planned / importance(high,medium,low) / status(introduced,hinted,revealed,resolved)
5. ai_generation_logs（AI生成日志表）
   log_id / novel_id / generation_type / context_used(JSON) /
   candidates(JSON) / selected_index / created_at

三、AI 调用流程（4 阶段）
1. 大纲生成阶段
   - 输入：创作简报（主题/背景/主线/关键转折点/结局方向）
   - 输出：结构化大纲（每个字段给 3-5 个候选选项）
   - 作者确认后：outline.status = confirmed
2. 章节规划阶段
   - 输入：已确认的大纲
   - 输出：章节列表（每章的章节目标/主要冲突/出场人物/关键事件）
   - 作者调整后确认：chapter_plans.status = planned
3. 逐章写作阶段
   - 输入：大纲 + 人物小传 + 当前章规划 + 前章结尾
   - 输出：3-5 个候选段落（场景/对话/过渡/心理 4 类型）
   - 作者选择后写入正文
4. 质量检查阶段
   - 每章写完，自动检测：大纲一致性 / 人物一致性 / 时间线 / 伏笔 / 衔接

四、界面设计
1. PC端主编辑器（三栏布局）
   ┌──────────┬───────────────────────┬──────────────┐
   │ 左侧栏 20% │      中间编辑区 55%      │  右侧辅助区 25% │
   │ 章节列表    │   正文写作区（最主要）     │  AI辅助面板    │
   │ 大纲入口    │                        │  当前章目标    │
   │ 人物库     │                        │  出场人物      │
   │ 伏笔追踪    │                        │  未回收伏笔    │
   └──────────┴───────────────────────┴──────────────┘
2. 大纲编辑界面
   - 主题/背景/主线/关键转折点/结局方向 每个字段有 [AI给几个选项]
   - 全部确认后 → [确认大纲，开始章节规划] → 🔒 锁定
3. AI 辅助面板（右侧栏）
   - 4 种生成类型：场景描写 / 人物对话 / 剧情过渡 / 心理活动
   - 候选方案卡片：上下文引用（"基于：第3章结尾 + 林晚语言指纹"）
   - [使用] [换一批] 按钮 + [我来说] 自由输入
4. 质量检查面板
   - 每章写完自动运行，报告用颜色标记（绿=通过 黄=警告 红=问题）
   - 问题项可一键修复
5. 移动端适配
   - 三栏改为上下堆叠，左侧栏变成顶部横向滚动，右侧辅助区变成底部弹出面板

五、执行要求
1. 先更新 PRD 和开发计划文档，把这套方案登记进去
2. 再按 DEV_PLAN 工作包逐个开发（每包有独立验收标准）
3. 每包开发完成后跑 Playwright 回归测试（含移动端视口）

六、验收标准（8 条）
1. 大纲确认后处于 🔒 锁定态，字段不可直接编辑
2. 章节规划由已确认大纲自动生成，可增删改排序
3. 编辑器右侧 AI 面板生成候选时展示"基于什么上下文"
4. 候选数量 3-5 个，[换一批] 换新一批，[我来说] 可输入
5. 写完章节自动出质量检查报告（5 项 + 颜色标记）
6. PC 三栏 20/55/25，移动端正确堆叠
7. 全流程 0 破链：简报 → 大纲 → 章节规划 → 编辑器
8. 0 第三方平台名；不接真 LLM（mock + window.AIHelper 钩子）
