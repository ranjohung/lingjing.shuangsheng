第二部分：ChatGPT《关于小说世界OS V2.0文档的意见》要点（用户认可）
=====================================================================
1. 诊断正确：AI把小说和游戏内容放进同一内容层是"AI乱改小说"的架构根因。
2. 有价值设计：Canon Lock（原著锁定）、L0-L6 分层、双引擎（Canon+World）、
   SHA-256 哈希校验、三种玩家身份（原著阅读者/世界游客/同人玩家）、
   定位转型"不是AI改编小说，是让小说成为一个可以走进去的世界"。
3. 修正一：不需要推翻"零删减+零创造"铁律，只需精确化为：
   · 主线（Canon）：100%原文，零删减，零改写
   · 支线（Branch）：AI可生成，但有约束
   · 探索/模拟（Simulation）：AI可生成，但不冒充原著
   → 产品宪法一句话："原著零删减，世界可扩展，主线不可篡改，支线允许创造。"
4. 修正二：L0-L6 七层架构分三阶段实现：
   第一阶段（MVP）：L0 SOURCE + L1 CANON + L2 PRESENTATION
   第二阶段：L3 INTERACTION + L4 SIMULATION
   第三阶段：L5 BRANCH + L6 WHAT-IF
5. 修正三：增加 L7 双生层（Dual Soul Layer）——角色从小说世界带出到心屿
   （保留亲密度≥80 + 完成个人线 + 支付灵晶条件）。
6. 修正四：补充小说上传质检的具体流程、检测算法、数据表。
7. 修正五："禁止聊天界面"只约束世界功能区，不约束心屿。

=====================================================================
第三部分：《小说世界OS V2.0》完整设计（修正版，开发依据）
=====================================================================

【第一：最高原则】
1. 原著零删减，世界可扩展，主线不可篡改，支线允许创造。
2. CANON IS TRUTH. AI IS INTERPRETER. WORLD IS EXPANSION. PLAYER IS PARTICIPANT.
3. AI不拥有CANON_WRITE权限。AI只能读取、分析、标记、演出、交互、扩展。

【第二：七层内容架构】
L0 SOURCE：原始文件，只读。
L1 CANON：原著正典层，不可修改。保存source_text_hash。
L2 PRESENTATION：演出层，AI生成镜头/动作/表情/背景/BGM，原文一句不删。
L3 INTERACTION：交互层，AI生成可点击的交互点。
L4 SIMULATION：世界生活层，AI生成家具/日常/NPC生活，标记SIMULATION非原著正文。
L5 BRANCH：支线层，AI生成非原著支线，标记"世界支线/灵境原创支线"。
L6 WHAT-IF：同人层，AI生成IF路线，标记"同人分支"。
L7 DUAL SOUL：双生层，角色从小说世界带出到心屿。

【第三：主线推进机制】
禁止：玩家输入→LLM→生成下一段小说。
正确：玩家当前状态→Canon Engine→寻找下一个Canon Anchor→读取作者原文→演出引擎→展示原文。
AI只负责"如何演"，不能负责"作者下一句写什么"。

【第四：四种内容标记】
【原著剧情】来自作者原文 /【世界探索】AI根据小说世界生成 /
【灵境支线】AI原创支线 /【同人分支】玩家进入非原著路线。
用户永远知道什么是作者写的，什么是灵境生成的。

【第五：原文完整性哈希】
上传时 source_text→SHA-256→source_hash；
每次生成世界前 Current Canon→Hash→与原始Hash比较；
不一致：Canon Integrity Failed，阻止发布。

【第六：小说上传质检（Novel Quality Gate）】
第一层 文本质量检测：完整性/章节顺序/乱码/重复章节/缺章/断章/OCR错误/
  人物名称一致性/时间线冲突/对话识别/段落完整性/敏感风险/来源信息/权利声明。
第二层 AI结构质量检测：生成《小说世界生成报告》
  （小说质量总分/人物一致性/时间线/地点关系/剧情完整性/章节完整性 + ⚠问题列表）。
第三层 作者确认：文本完整/人物名称/章节/世界观/拥有上传使用权利 → 开始生成。
第四层 AI World Compiler：World Bible/Character Bible/Location Bible/Object Bible/
  Timeline/Canon Graph/Scene Graph/Interaction Graph/Quest Graph/Relationship Graph/Asset Manifest。
第五层 自动质量测试：Canon QA/Continuity QA/Interaction QA/State QA/Branch QA。

【第七：收费系统】
1. 不切原著正文收费。收费在新增价值：特殊路线/同人路线/特殊场景/特殊互动/
   服装/家具/CG/特殊结局。
2. AI只推荐收费点（星级+原因+建议灵玉价），作者决定 [接受][修改价格][取消][改广告][改会员]。
3. AI绝对不能自动给原著增加收费障碍（人为堵路伤口碑）。

【第八：三种玩家身份】
模式A 原著阅读者：完整体验小说，不改主线。
模式B 世界游客：进入世界逛（街市/酒馆/观察角色/买东西/听NPC聊天），主线仍按原著。
模式C 同人玩家：选择身份（原著主角/原创角色/路人/配角/自定义），不破坏主线进行自己的故事。

【第九：数据表】
source_novels / canon_anchors / presentation_data / interaction_points /
simulation_content / branch_records / whatif_records / dual_soul_characters /
player_states / novel_quality_reports / world_generation_logs。

【第十：核心铁律】
1. 零删减：主线剧情100%使用作者原文。
2. 零创造：主线不创造，只演出。
3. 主线锚点+支线收敛：偏离原著时AI生成支线，2-3节点后收敛回主线。
4. 点击推进：场景人物没变播放下一句，变了跳转下一界面。
5. 禁止聊天界面（只约束世界功能区，不约束心屿）。
6. 虚拟币双轨制：平台用灵晶/灵玉；小说世界内用铜钱/银两。

【验收标准】
1. 上传小说后，系统自动质检并生成报告。
2. Canon层内容不可修改，有SHA-256哈希校验。
3. 主线推进由Canon Anchor驱动，不是LLM自由生成。
4. 演出层为原文添加镜头/动作/表情，原文一句不删。
5. 交互层可点击书桌/窗户/角色，产生探索内容。
6. 模拟层生成家具/日常/NPC生活，标记为SIMULATION。
7. 支线层AI生成支线，2-3节点后收敛回主线。
8. IF层玩家可以进入同人路线。
9. 双生层角色可以带出到心屿。
10. 四种内容标记视觉区分。
11. 收费点由作者控制，AI只推荐。
12. 三种玩家身份可选。

【视觉风格（用户补充指令）】
二次元摄影画面风格：赛璐璐动漫人物 + 摄影级光影/景深/胶片颗粒，
演出层全部素材按此风格 token 出图（本项目 prototype 用 CSS 光影体系 + AI 生成示例图模拟）。
