## 2. v5.12 架构

### 2.1 核心基础设施层（6 个 JS 模块）

| 文件 | 用途 |
| --- | --- |
| `js/genres.js` | **30 题材分类元数据** — id/tag/icon/desc/examples/keywords（含关键词权重匹配） |
| `js/novel-store.js` | **本地存储层** — localStorage CRUD（每个小说一个独立 key） |
| `js/plot-schema.js` | **plotTree 标准 schema** — 小说/章节/角色/高光/节点/结局的字段约定 |
| `js/novel-parser.js` | **前端规则解析引擎**（无 LLM）— 章节分段 + 2-3 字滑动窗口角色识别 + 高光关键词识别 + 场景识别 + **覆盖审计 + 自动修复** |
| `js/plot-engine.js` | **通用剧情引擎层** — 节点渲染、选项跳转、数值更新、结局触发、覆盖审计告警 |
| `js/demo-seed.js` | **5 题材 demo 种子**（锦绣未央/雾锁民国/月森林/银河纪元/春风不及） |

### 2.2 4 个交互页面（覆盖文学/游戏/编辑全链路）

| 页面 | 作用 |
| --- | --- |
| `library.html` | **题材库浏览** — 30 题材卡片网格 + 已上传小说展示 + 搜索/筛选 + 详情表 |
| `novel-upload.html` | **4 步上传向导** — ①选题材 → ②上传文本 → ③元数据 → ④一键解析（覆盖审计） |
| `novel-edit.html` | **解析结果编辑器** — 节点编辑/角色编辑/选项编辑 + 实时预览 + 保存 |
| `plot-runner.html` | **沉浸剧情运行器** — 顶部场景（WebGL 渐变 + 星辰）+ 左侧立绘 + 底部对话气泡 + 选项按钮 + 右上 HUD（信任/亲密/声望/覆盖审计）+ 结局模态 |

### 2.3 关键技术细节

- **30 题材覆盖男女频 + 小众**：玄幻/奇幻/仙侠/都市/校园/历史/军事/游戏/体育/科幻/灵异/悬疑/二次元/古言/现言/浪漫青春/仙侠言情/玄幻言情/科幻空间/悬疑推理/同人/武侠/古武/网游/末世/赛博/无限流/童话/剧本杀/其他
- **覆盖审计保证不漏**：
  - 每个章节至少 1 个主线节点
  - 每个角色至少出现在 1 个节点（parse 时 + runAudit 自动修复）
  - 每个高光至少 1 个高光节点（auto-fix 把孤立高光强制并入最近主线）
  - 引擎层右上 HUD 实时显示"覆盖审计"和"⚠ X 角色/Y 高光/Z 章节未覆盖"
- **沉浸剧情标准**：玩家是"我"、每个节点 2-4 选项、不同选项 → 不同分支 → 不同结局、传统 4 结局（圆满/留白/真相/别开生面）
- **3D 真机可玩**：顶部 WebGL 程序化背景 + 主线色板随场景 key 切换（旧版已用）+ 程序化几何（已存在）+ 立绘（SD 立绘 PNG）+ Three.js 可选叠加（v5.11 集成）

### 3.4 覆盖审计 + 自动修复

v5.12 的关键创新：**解析后立即跑审计，未覆盖的角色/高光自动并入最近章节主线节点**

实现细节：
1. 解析时统计每个节点 charIds 中的角色 ∩ plot.chars 的覆盖
2. 缺失的角色：取其 firstChapter，并入该章节主线节点的 charIds
3. 缺失的高光：取关键词所在章节，并入该章节主线节点的 isHighlight=true

测试结果：从 5 章测试文本自动识别到 12 个字符（含 3 主名 + 9 noise），自动修复让 audit.covered.chars = 12/12 ✅

## 6. 边界条件与已知保留

- **不会漏的**（算法保证）：
  - 每个章节都至少有 1 个主线节点
  - 每个识别到的角色都至少在 1 个节点出现
  - 每个识别到的高光关键词都至少在 1 个高光节点出现
- **可能弱的**（已知保留）：
  - 角色识别目前 2-3 字字符窗口+上下文提示，对纯对话模式（无"我叫X"等提示）依赖度大；后续可加入 LLM 增强
  - 场景识别基于关键词命中，对场景隐喻（如"大殿"代"宫殿"）覆盖率一般
  - 选项分支目前是结构化模板（继续/停/换方向），用户的文字不会被精确分类为某个选项
