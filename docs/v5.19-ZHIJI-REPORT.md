# v5.19 — 知己 · AI 陪伴功能区重建

**日期**：2026-09-10 23:50
**版本**：v5.19（前端 UI 新增功能区 + 设计系统扩展）

**用户反馈（截图驱动）**：
> "home (library.html) 移动视图（412px）— 顶部 nav 用了 `hidden md:flex`，整个 nav 在 mobile 直接被隐藏，**AI 陪伴功能区完全消失**了。应该有个底部 tab bar（移动端），名字我想了想就叫 **知己**（比 AI 陪伴更亲切）。参考即时情感陪伴类 App 的布局：主页 / 陪聊 / 记忆 / 我的，底部 tab bar。"

---

## 一、问题诊断

### 1.1 顶级 nav 设计选择错

library.html 顶部 nav 用 `hidden md:flex`（仅 ≥768px 显示），结果：

| 视图 | 顶级 nav | AI 陪伴入口 |
|---|---|---|
| PC（≥768px） | 显示 | ✗ 没有入口 |
| 移动端（≤767px）| **整个隐藏** | ✗ 完全消失 |

**根因**：将 mobile-only 功能塞进了只在 PC 显示的顶部 nav。

### 1.2 体验原则违背

- **认知层级错位**：情感陪伴是核心场景（C 位玩法），却作为顶级 nav 副项被随意隐藏
- **跨设备一致性**：mobile 用户感知不到"陪伴功能区存在"
- **导航未覆盖**：用户必须"知道有这页面"才能去，但不知道从哪儿发现

### 1.3 命名考究（"知己"）

候选词对比：

| 候选 | 优点 | 缺点 |
|---|---|---|
| AI 陪伴 | 准确 | 工程腔，客户共鸣弱 |
| 数字伴侣 | 直观 | 像 SEO 关键词 |
| 灵伴 | 有品牌感 | 但"伴"字太重 |
| **知己** | **古朴、亲切、"一个角色两种人生"自然贴合** | 传统意象，需 modern UI 托底 |

**决策**：`知己`——呼应产品 slogan「在故事里经历命运，在现实中陪伴你」，强调"懂你的另一半"。

```
│                                      │
│              内容区                   │
│                                      │
│                                      │
├──────────────────────────────────────┤
│  ds-bottom-tabs                      │
│  主页 📚 / 知己 💞 / 我的 👤 ...      │
└──────────────────────────────────────┘
```

**4 个新页面**：

| 文件 | 行数 | 角色 |
|---|---|---|
| `companion.html` | 220 | 主页：今日心情 / 6 位角色动态卡 / 进入陪聊 |
| `chat.html` | 143 | 1v1 陪聊：阿岁 / 角色头 / 消息气泡 / 输入栏 |
| `memory.html` | 172 | 共享记忆时间线 / 情绪曲线 / 3 角色 / 27 记忆条目 |
| `profile.html` | 203 | 个人主页 / 用户画像 / AI 偏好 / 订阅 / 关于 |

**library.html 改造**：
- 顶部 nav 加 `💞 知己` 链接 → `companion.html`（PC 可见）
- 文末加 `ds-top-tabs` 移动底部 tab（小说世界 / 知己 / 创作者），mobile 显示，PC 隐藏
- 链路 `css/design-system.css` + `body { padding-bottom: 76px; }`

### 2.2 设计语言：心色调

v5.18 的 design-system.css 是紫色 + 琥珀金（"创作者向"），v5.19 补一份**心色调**（情感陪伴向）：

```
粉紫渐变：#2a1556 → #5d1f5f → #7a3869（情绪温度）
暖光：#e8c75a（角色头像 glow / 心情横幅）
背景：#0a0717（深紫黑，比创作者向更深，更安静）
最大宽：520px（移动优先）
```

**为什么独立审美**：玩家进入陪伴区希望"降噪、私密、温暖"，与创作者区的"高效、理性、专业"形成对比。

### 2.3 设计系统扩展（v5.19 delta）

`css/design-system.css` 从 1009 行 → **1209 行**（+200 行）：

| 类 | 用途 | 行为 |
|---|---|---|
| `ds-mh` | 移动顶部 header | 横向 flex：左返回 / 中标题 / 右动作 |
| `ds-mh-title` | 标题 | `flex:1`，单行截断 |
| `ds-mh-subtitle` | 副标题 | 11px，50% 白 |
| `ds-icon-btn` | 圆形 36×36 图标按钮 | hover 12% 白 |
| `ds-bottom-tabs` | 底部 tab bar | fixed 底部 + 90% 黑背景 + 6px shadow |
| `ds-bottom-tab` | 单 tab | 图标 + 文字，active 琥珀色 + scale 1.1 |
| `ds-top-tabs` | 备用名（library 用了） | 同 ds-bottom-tabs，等价 |

**响应式断点**：mobile (≤767px) 显示 bottom-tabs，PC (≥768px) 显示顶部 nav。两者互斥。

### 2.4 视觉风格术语统一（重要）

| 类别 | v5.19 命名 | 含义 |
|---|---|---|
| 顶部导航 | **顶部 nav**（PC 顶部水平菜单） | library / creator-center 用的 |
| 移动底部导航 | **底部 tab bar**（mobile 固定底部） | 知己 4 页用的 |
| 移动头部 | **ds-mh**（移动头部固定顶） | 每页都有 |
| 返回箭头 | **ds-back-arrow** | 全局统一 |

——这些是 v5.19 沉淀的"工程语义"，后续不要混用。

## 四、关键 UX 改进

1. **底部 tab bar 替代策略**：mobile 端不能只在顶部 nav 放入口；任何"永恒在场"的功能，必须在 mobile 有底部入口
2. **功能区命名**：AI 陪伴 → **知己**（情感共鸣 + 品牌感 + 模式识别成本低）
3. **视觉风格双轨**：创作者向（紫 + 琥珀）/ 陪伴向（粉紫 + 心暖），每个区有专属色温
4. **顶部 nav 不滥用**：每个顶级 tab 必须有清晰业务边界（v5.18 已立的规矩）

## 五、约束（写入 MEMORY.md 的工程硬规则）

1. **mobile 必有底部 tab bar**：不能只在顶部 nav 用 `hidden md:flex`
2. **返回箭头统一 class**：`ds-back-arrow`（不再硬编码 `back-arrow`）
3. **第三方产品名禁用**：包括对标参考词
4. **顶部 nav tab 不随便加**：每个 tab 必须有清晰业务边界，不加空架子
