## 1. 设计原则（用户需求）

> "对标星野和沉浸剧情对话游戏的手机游戏，每个功能区就是这个功能区内容而不是滑动到别的功能区"

### 解决思路
- **从 Next.js 5 Tab 滑动** → 改为**单文件 HTML 多视图**（home / novel-list / novel-detail / game / companion / studio / discover）
- **每个功能区是独立完整内容**：点进去就是那个功能区的全部内容，不会滑动切换
- **移动端底部 4 Tab**：主页 / 陪伴 / 小说（CTA）/ 创作（不是滑动切换区，是切换整个视图）
- **桌面侧栏**：v5.8 暂用 4 移动 Tab 兼容（mobile-first）

### 关键参考
- **星野**（字节跳动 AI 角色陪伴）：每个 AI 角色独立完整界面、不混内容
- **沉浸剧情游戏**（互动阅读平台）：作品封面 + 章节列表 + 视觉小说风格游戏页

## 2. 整体架构

### 单文件 `output/preview/redesign.html`（1180 行）

```
7 个视图（.view.active 切换）：
├── home         — 我的世界（Hero 角色 + 功能区卡片网格 + 最近在玩）
├── novel-list   — 小说世界（顶部题材 chip + 当前题材小说卡片网格）

├── studio       — 创作中心（占位）
└── discover     — 发现（占位）
```

## 6. 技术亮点

### 单文件 HTML
- **零依赖**：无 React/Vue/Next.js，纯 vanilla
- **零构建**：双击即看（移动端 viewport 适配）
- **零外部资源**：BGM/SFX 全程序化（v5.7）+ 立绘/场景 PNG 复用 assets
- **持久化**：localStorage `ljss_save_v5_8`（自动存档）

### 路径修复
- `assets/portraits/` → `portraits/`（server root 相对路径）
- 9 个 GENRE 各自用对应 scene/portrait

### 函数暴露
- `window.selectGenre / openNovel / startGame / goView` 暴露给 playwright eval
